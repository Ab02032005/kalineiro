# Kali

Модульная AI-платформа: собственное ядро, память, знания, инструменты и безопасность. Языковые модели подключаются как взаимозаменяемые модули.

> Текущий статус: **этап 2 — основа проекта.** Работают настройки, JSON-логи, `/health` и тесты. Ядро, память и интерфейс — на следующих этапах. План см. в `docs/PLAN.md`.

## Структура

- `backend/` — Python-пакет `kali`, тесты, Dockerfile.
- `infra/` — Docker Compose.
- `docs/` — архитектура и план.
- `data/` — локальные данные (не в Git).

## Быстрый старт (без Docker)

```powershell
cd Kali\backend
python -m venv .venv
.\.venv\Scripts\activate
pip install -e ".[dev]"
pytest
python -m kali
```

Затем откройте http://127.0.0.1:8000/health — должно вернуться `{"status": "ok", ...}`.

## Запуск через Docker

Нужен запущенный Docker Desktop.

```powershell
cd Kali
copy .env.example .env
docker compose -f infra/docker-compose.yml up --build
```

## Конфигурация

Все настройки — переменные окружения с префиксом `KALI_` (см. `.env.example`). Секреты не выводятся в логи. В `prod` отключена документация API.

## Проверки

- `ruff check kali tests` — стиль и ошибки.
- `pytest` — тесты.
- CI в `.github/workflows/ci.yml` запускает оба и собирает образ.

## Вход и пользователи (этап 8)

Все данные Kali доступны только после входа. Открытой регистрации нет: учётные записи создаёт администратор из командной строки.

Создать первого администратора (на компьютере, где запущен Kali):

```powershell
cd Kali\backend
.\.venv\Scripts\python.exe -m kali.cli create-user --username admin --role admin
```

В Docker — внутри контейнера:

```powershell
docker exec -it infra-backend-1 python -m kali.cli create-user --username admin --role admin
```

Другие команды: `list-users`, роли `admin` и `user`. Пароль должен быть не короче 10 символов и не совпадать с логином. Сессия живёт 12 часов (`KALI_AUTH_SESSION_HOURS`). После нескольких неудачных попыток входа с одного адреса вход временно блокируется.

Что защищено: память, база знаний, файлы, агенты, чат и статистика доступны только вошедшим; управление пользователями, статус администратора и журнал событий — только администратору. Пароли хранятся в виде scrypt-хэша, токены сессий — в виде SHA-256. Журнал фиксирует входы, неудачные попытки, создание пользователей и разрешение действий агентов.
